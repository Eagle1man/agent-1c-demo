# Демо-агент для 1С

Небольшой ИИ-агент для работы с 1С (бесплатная учебная версия), собранный по
концепции гуманистического ИИ-агентного управления: **агент выполняет работу —
человек принимает решения**. Профили: **бухгалтер** и **логист**.

## Состав проекта

| Файл | Назначение |
|---|---|
| `PROTOCOL.md` | протокол обмена v1.0 — единственный контракт «агент ↔ 1С» |
| `agent/agent.py` | чат-агент: Ollama (tool calling) или демо-режим без модели |
| `agent/bridge.py` | файловый мост: команды/ответы, таймаут, журнал |
| `agent/tools.py` | инструменты, уровни риска, подтверждение человека |
| `agent/mock_bridge.py` | эмулятор 1С — проверки без установленной 1С |
| `agent/config.json` | путь exchange, профиль, модель, пользователь |
| `agent/test_demo.py` | сквозной автотест (mock, без 1С и без Ollama) |
| `agent/web_app.py` | веб-интерфейс (stdlib, без зависимостей): чат + карточки «Данные из 1С» + кнопки подтверждения |
| `1c/АгентМост.bsl`, `1c/ИНСТРУКЦИЯ_1С.md` | **часть opencode** (приёмка: `verify_1c.py`) |
| `fixtures/` | эталонные JSON-команды и ответы протокола |
| `dataset/dataset.jsonl` | стартовый датасет «ситуация → действие» (под LoRA) |

## 0. Демонстрация в один клик (exe + ярлык)

- **Ярлык:** «Демо — ИИ-агент 1С» на рабочем столе (создан) — ведёт на
  `dist\demo_agent_1c.exe` (one-file ≈55 МБ, Python на машине не нужен).
- Двойной клик по ярлыку **сразу открывает веб-интерфейс в браузере**
  (http://127.0.0.1:8000): exe сам поднимает **эмулятор 1С** и наглядные
  карточки «Данные из 1С»; ничего вводить в консоли не нужно.
- Консольный чат (как раньше): `demo_agent_1c.exe --cli` или
  `demo_agent_1c.exe --cli --no-mock`.
- exe сам поднимает **эмулятор 1С** и подключает **локальную модель Ollama**;
  папка обмена `dist\exchange` создаётся рядом (журнал показа —
  `dist\exchange\journal.jsonl`).
- На машине без Ollama агент не падает — работает демо-режим по ключевым словам.

## 0а. Подключение живой 1С (без перезапуска)

1. Поставьте бесплатную 1С (раздел 3): комьюнити-лицензия + учебная
   «Управление торговлей» (для накладных) или «Бухгалтерия» (для чтения).
2. В 1С откройте `АгентМост.epf` по `1c/ИНСТРУКЦИЯ_1С.md`, в поле пути
   укажите папку обмена exe: `dist\exchange`, нажмите «Запустить мост».
3. В веб-интерфейсе нажмите **«Живая 1С»** (эмулятор выключится без
   перезапуска). Статус-бар должен показать платформу настоящей 1С
   вместо «(mock)».
4. Прогоните показательный сценарий — цифры теперь из вашей базы.
   Назад к эмулятору — кнопка **«Эмулятор»**.
- Настоящая 1С вместо эмулятора: кнопка **«Живая 1С»** в веб-интерфейсе
  (эмулятор выключается без перезапуска; ★-путь в мосте указать на папку
  `dist\exchange`). См. раздел «0а. Подключение живой 1С».
- Пересборка exe:
  ```bat
  py -3 -m PyInstaller --onefile --name demo_agent_1c --add-data "agent\config.json;." --distpath dist --workpath build --specpath . --clean -y agent\agent.py
  ```


## 2. Демо с эмулятором 1С (интерактив, без установки 1С)

```bat
py -3 agent\agent.py --mock
```

Фразы: «проверь связь», «остатки на складе», «задолженность контрагентов»,
«сколько заказов», «создай накладную на ООО Ромашка 10 шт».
Команды: `/бухгалтер`, `/логист`, `/помощь`, `/выход`.

## 2а. Веб-интерфейс (наглядно, что данные из 1С)

```bat
py -3 agent\web_app.py --mock
```

Открыть в браузере: http://127.0.0.1:8000

Что видно (этого не было в консоли):
- статус-бар: жива ли 1С, платформа (`platform`), версия моста, режим
  (эмулятор mock / настоящая 1С), путь exchange, счётчик журнала;
- каждый ответ 1С — карточка с зелёным бейджем
  «⬢ Данные из 1С · мост АгентМост 1.0 · действие · id · исполнитель»,
  таблицы — настоящими HTML-таблицами, сырой JSON из `exchange/responses`
  раскрывается по клику (доказательство источника);
- создание документа — карточка «⚠ Высокий риск» с кнопками «Да, создать» /
  «Нет» вместо ввода «да» в консоль (двухступенчатая защита та же);
- кнопки быстрых команд и кнопка «Журнал решений» (`exchange/journal.jsonl`).

С настоящей 1С вместо эмулятора:
```bat
py -3 agent\web_app.py --no-mock --exchange ..\exchange
```

## 3. Полное демо с настоящей 1С (бесплатно)

Бесплатные варианты с официального сайта (проверено на v8.1c.ru, раздел
«Учебные версии программ 1С»):

1. **Комьюнити-лицензия** — лучший вариант для нашего агента: бесплатная,
   без функциональных ограничений для разработки (платформа 8.3.23+,
   файловый и клиент-серверный режимы). Получение: регистрация с телефоном
   на developer.1c.ru. Нюанс: не для реального учёта, только разработка —
   для демо это как раз то, что нужно (снимает учебные лимиты).
2. **«1С:Предприятие 8.3. Версия для обучения программированию»**
   (электронная версия) — бесплатное скачивание дистрибутива платформы,
   всё нужное для разработки и демо.
3. **«1С:Бухгалтерия 8. Учебная версия»** — для профиля «бухгалтер».
   Нюанс для агента: в Бухгалтерии нет документа `РеализацияТоваровУслуг`
   (мост ответит `unsupported_doc_type` — это нормально), работают
   `проверка_связи` и чтение (`запрос_1с`).
4. Для профиля «логист» (документ `РеализацияТоваровУслуг` из коробки) —
   учебная **«Управление торговлей»**.

Старый текст ниже — как было:

1. **Учебная версия 1С** — на официальном портале `online.1c.ru` (раздел
   «Бесплатно»): «1С:Предприятие 8. Учебная версия» и бесплатные сборки
   платформы с конфигурациями «Управление торговлей 3.0» (логист) и
   «Бухгалтерия/Управление нашей фирмой» (бухгалтер).
   Ограничения: 1 сеанс, лимит 2000 записей, нет COM/HTTP — поэтому обмен
   идёт файлами.
2. **Мост в 1С** — см. `1c/ИНСТРУКЦИЯ_1С.md` (внешняя обработка,
   кнопка «Запустить мост»).
3. **Локальная модель** (бесплатно, данные не покидают компьютер): Ollama уже
   установлен, модель **qwen2.5:1.5b** скачана (`ollama list`) — можно сразу
   запускать агента. При желании крупнее и точнее:
   ```bat
   ollama pull qwen3:4b
   ```
   и правка `agent/config.json`, поле `model`.
4. **Запуск агента** (без `--mock`):
   ```bat
   py -3 agent\agent.py
   ```
   Агент сам проверит наличие Ollama; если его нет — откроется демо-режим.

## 4. Сценарий показа ректору (5 минут)

Главная кнопка — **«▶ Показательный сценарий: справка для руководства»**:
агент сам выполняет многошаговое задание, каждый шаг виден:
фиолетовые карточки «🧠 Замысел агента» → зелёные «Данные из 1С» → итог.

1. **Замысел:** агент озвучивает план (проверить связь → 3 запроса → итоги → решение).
2. **Автономность:** остатки, задолженность и заказы забирает из 1С сам (низкий риск).
3. **Работа, а не витрина:** итоги считает сам — пустые остатки, сумма долгов, число заказов.
4. **Остановка перед риском:** проект накладной готовит, но не создаёт —
   ждёт «Да/Нет» человека. Нажмите «Нет» → «документ НЕ создан»;
   повторите сценарий и нажмите «Да» → номер проведённого документа.
5. Откройте **«Журнал решений»**: каждое действие — с риском и решением
   (`auto` / `awaiting_human` / `human_confirmed` / `human_rejected`).
6. Контрольный вопрос: «откуда цифры?» — под каждой карточкой id запроса
   и сырой JSON из `exchange/responses`.

Старый ручной сценарий (по кнопкам):

1. «проверь связь» → платформа и версия моста.
2. «остатки на складе» → таблица (низкий риск — агент сам).
3. «задолженность контрагентов» → таблица.
4. «создай накладную на ООО Ромашка 10 шт» → агент покажет эхо и спросит;
   «нет» → ничего не создано; повтор и «да» → номер документа.
5. Открыть `exchange/journal.jsonl` — каждое действие с уровнем риска и
   решением (`auto` / `human_confirmed` / `human_rejected`).

## 5. Как это связано с концепцией

- **Адаптивная автономность:** низкий риск (запросы) — выполняется сам;
  высокий (создание документов) — только после подтверждения человека.
  Защита двух уровней: код агента **и** код моста 1С (`confirmed_by`).
- **Журнал действий** с обоснованием каждого шага — `exchange/journal.jsonl`.
- **Локальная LLM (Qwen через Ollama)** — данные не уходят на сторону (152-ФЗ).
- **`dataset/dataset.jsonl`** — ровно формат «ситуация → действие» для будущего
  дообучения LoRA на студенческой практике (разделы 3 и 5 концепции).

## 6. Совместимость с opencode

Контракт — только `PROTOCOL.md`. opencode пишет исключительно `1c/*`,
Cline — всё остальное. Приёмка его части: `py -3 verify_1c.py`
(маркеры протокола, запрет COM/HTTP, полнота инструкции).

## 7. Ограничения

- Учебная версия 1С: 1 сеанс, 2000 записей (поэтому `ПЕРВЫЕ 50`), нет
  COM/HTTP-сервисов — обмен только файлами.
- `.bsl` выполняется в живой 1С; машинная проверка — `verify_1c.py`
  (маркеры и запреты), полный прогон — после установки учебной версии.
- Демо-режим понимает ограниченный набор фраз; для свободного языка нужна
  модель Ollama (шаг 3).
