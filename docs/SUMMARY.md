## 3. Главные решения и почему

1. **Файловый мост, а не COM/HTTP.** Учебная 1С не даёт COM; файловый обмен
   проверен и не требует открытых портов на базе.
2. **Без Next.js/Superset/Grafana.** ТЗ §40.7 запрещает фреймворки ради моды;
   страница на чистом JS+SVG весит 14 КБ, работает офлайн и разворачивается
   копированием папки.
3. **OPC UA предусмотрен, но не имитируется.** Сервера нет — панель честно
   показывает «не подключён»; коннектор написан под белый список узлов.
4. **Запись отключена полностью.** Демо физически не может изменить данные в 1С
   или отправить команду оборудованию.

## 4. Что исправлено по дороге (реальные дефекты)

- мост не компилировался в тонком клиенте: серверные типы в клиентском контексте;
- модуль падал на строке с `\"` вместо `""` и на дубле имени процедуры;
- путь обмена в реквизите формы обнулялся — тик писал лог в `D:\log`;
- панель отдавала 500, если 1С ещё держала файл ответа;
- RAG-индекс был собран англоязычной моделью на русских текстах;
- первый вопрос к RAG занимал 93 с без прогрева.

## 5. Ограничения (честно)

| Ограничение | Следствие |
|---|---|
| Проверено на учебной базе `ДемоАгент` | на рабочей конфигурации набор объектов может отличаться |
| OPC UA сервера нет | производственных данных в панели нет |
| Выгрузка CSV — 50 строк | ограничение файлового моста, подписано в файле |
| Версия платформы в ответе моста — «8.3» | заглушка; честный вызов ломает форму, отдельная задача |
| Доступ только с localhost | для других машин нужен обратный прокси с аутентификацией |
| Маршрутизация чата по ключевым словам | свободный язык ограничен; LLM-маршрутизация — следующий шаг |

## 6. Что нужно для эксплуатации на предприятии

1. **Доступ к рабочей 1С** — отдельная учётная запись только на чтение.
2. **OPC UA:** endpoint, политика безопасности, сертификат клиента, список узлов.
3. **Роль утверждающего** — кто подтверждает действия, если включать запись.
4. **Где размещать:** сервер в сети предприятия, резервное копирование журналов.
