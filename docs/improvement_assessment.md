## 4. Работа с Ollama

### Механизм вызова (`agent/web_app.py`, функция `ollama_call`)
- URL: `http://localhost:11434/api/generate`
- Модель: `qwen2.5:1.5b`
- `stream: False`
- Таймаут: 60 секунд

### Интеграция
- `chat_service.py` импортирует `qwen_route, QWEN_MODEL, QWEN_URL` из `web_app.py`
- `config.json`: `"model": "qwen2.5:1.5b"`, `"timeout_sec": 15`
- `agent.py`: режим `ollama` и режим `demo` (ключевые слова)

### Статус Ollama на момент аудита
- **Не запущен.** Порт 11434 недоступен. Вызовы Ollama возвращают ошибку соединения.
- Вызывает `rag_answer(question)` из `rag/search.py`
- История хранится только в памяти, не сохраняется на диск

### Веб-чат (`agent/web_chat.py`)
- Flask, порт 5000, тот же `rag_answer`, без Ollama

## 5. Интеграция с 1С

### Реальный мост (`agent/bridge.py`)
- Файловый протокол v1.0 через `exchange/commands/` → `exchange/responses/`
- Атоматическая запись через `.tmp` файл, таймаут ожидания ответа (по умолчанию 15 сек)
- `Bridge`, `BridgeTimeout`, `BridgeError`
- Журнал действий: `journal.jsonl`, лог: `log/agent.log`

### BSL-обработка (`1c/АгентМост.bsl`)
- Форма в 1С: кнопка «Запустить мост», чтение команд, запись ответов
- Поддержка всех 7 агентов, журнал аудита, безопасность доступа

### Эмулятор (`agent/mock_bridge.py`)
- `Mock1C` — повторяет протокол v1.0, валидация запросов (запрет `ИЗМЕНИТЬ`, `УДАЛИТЬ`, `;`)
- Два подтверждения для создания документа, демо-данные (ООО Ромашка, Товар А и т.д.)

### Уровни риска (`agent/tools.py`, `RISK`)
| Действие | Риск | Подтверждение |
|---|---|---|
| `проверка_связи` | low | Авто |
| `запрос_1с` | low | Авто |
| `создать_документ` | high | Human-in-the-loop (ввод «да») |

## 6. Обработка ошибок

| Компонент | Механизм | Категории ошибок |
|---|---|---|
| `bridge.py` | `BridgeTimeout`, `BridgeError` | Таймаут моста, ошибки протокола |
| `Mock1C` | `parse_error`, `invalid_query`, `unsupported_action` | Некорректный запрос, недопустимая операция |
| `chat_service.py` | `try/except` в `process()` | Сбой службы, возвращает `{"status": "error"}` |
| `base_agent.py` | `try/except` в `_tick()` | Ошибки тика агента, пишутся в `journal.jsonl` |
| `web_app.py` | `try/except` в `_process_message()` | Ошибки обработки веб-сообщений |

**Проблемы:**
- Нет централизованного класса обработки ошибок с категориями (поиск/модель/1С/бизнес-правила/неоднозначность/неизвестная причина)
- Нет классификации ошибок по степени влияния на пользователя
- Нет механизма повторного выполнения после сбоя (кроме базового таймаута в Bridge)

## 12. Критерии приёмки

1. Существующий пользовательский чат продолжает работать
2. События регистрируются и доступны для анализа
3. Можно найти повторяющиеся ошибки
4. Фоновый аналитик формирует отчёт
5. Результаты фонового анализа сохраняются после перезапуска
6. Кандидаты на улучшение не становятся рабочими автоматически
7. Регрессионные тесты запускаются воспроизводимо
8. Отчёт различает подтверждённые результаты и гипотезы
9. Ошибка фонового анализа не приводит к бесконечным повторным запускам
10. Нет непредусмотренных операций записи в рабочую 1С
11. Существующие тесты не ухудшились без объяснённой причины
12. Документация описывает запуск, конфигурацию, ограничения и откат
