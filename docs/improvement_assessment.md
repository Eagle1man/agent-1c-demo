# Оценка текущего состояния и что можно переиспользовать

**Дата:** 01.11.2026 (переписано; прежняя версия была повреждена при склейке частей и содержала неверные утверждения)

Полный аудит: `docs/audit_report.md`. Инвентаризация: `docs/integration_inventory.md`.

## Что переиспользуем без переписывания

| Компонент | Почему годится |
|---|---|
| `PROTOCOL.md` + `1c/АгентМост.bsl` + `verify_1c.py` | контракт принят, проверка автоматическая, менять не нужно |
| `agent/bridge.py`, `mock_bridge.py` | таймауты, атомарная запись, журнал; мок повторяет протокол |
| `agent/event_logger.py` | соответствует ТЗ §17, обезличивание и безопасная запись |
| `agent/problem_registry.py`, `skills_catalog.py` | закрывают §18 и §20, покрыты тестами |
| `rag/index_build.py`, `rag/search.py` | индекс и поиск измерены |
| `agent/tools.py` | уровни риска и human-in-the-loop |

## Что требует доработки

| Компонент | Проблема |
|---|---|
| `agent/web_app.py` | показывает демо-данные, нет единой панели предприятия |
| `agent/coordinator.py` | декомпозиция по ключевым словам, без вызова MCP |
| `agent/skills_catalog.py` | не подключён к работе агентов |
| `agent/models.py` | роли размечены, крупная модель ждёт ВМ с GPU |

## Что отсутствует

MCP-слой, политика разрешений, OPC UA-адаптер, единая панель на реальных данных, цифровой двойник, ночной контур улучшения.

## Ключевой вывод аудита

Проект — рабочий демонстрационный контур 1С (чат, RAG, эмулятор, мост), а не целевая система. Оценка «70% готовности» из старых документов относилась к демо и не учитывала, что мультиагентный слой не импортировался, а SCADA отсутствует. Фактическая готовность к пилоту на 1С — после проверки живого обмена.
