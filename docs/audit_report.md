## 3. Архитектурные пробелы

| Пробел | Почему важен |
|---|---|
| Нет MCP-слоя | агенты пока ходят в адаптеры напрямую; нет единой проверки прав |
| Реестр навыков не подключён | версии и статусы есть в коде, но агенты их не используют |
| Нет политики разрешений | право на инструмент сейчас определяется только кодом инструмента |
| Нет единой панели на реальных данных | веб-интерфейс показывает демо-карточки |
| Нет OPC UA-адаптера | промышленный уровень отсутствует |
| Нет двойника | нельзя проверить последствия решения |
| Один экземпляр модели на все роли | дорого для диалога, слабо для анализа (частично решено `agent/models.py`) |

## 4. Минимальный пилот

**Процесс:** «заказ на продажу → доступность материалов → срок → решение».
**Почему он:** опирается только на 1С, проверяем без SCADA, и его хватает для сквозного сценария ТЗ §15.

| Что нужно | Состояние |
|---|---|
| чтение заказа, остатков, документов из 1С | мост готов, живой прогон — нет |
| ответ с источниками | есть |
| проект изменения (без исполнения) | есть (эхо документа) |
| подтверждение человека | есть |
| панель с карточками заказа и материалов | нужно собрать на реальных данных |
| проверка ограничений | детерминированный код, частично |

**Критерий приёмки пилота:** на вопрос «почему заказ задерживается» система отвечает, указывая для каждого факта источник (документ 1С или справочник), время получения и не подставляя ничего от себя.

## 5. План работ (последовательность владельца)

| № | Этап | Результат | Зависимость |
|---|---|---|---|
| 1 | Проверить живой обмен с 1С | таблица доступных объектов, `проверка_связи` с реальной платформой | 1С запущена |
| 2 | Чтение из 1С + единая панель | карточки заказа/материалов на реальных данных, чат с источниками | шаг 1 |
| 3 | OPC UA на тестовом сервере | адаптер чтения разрешённых узлов, режим `opcua` | endpoint и узлы |
| 4 | Единый MCP-слой и политика | агенты ходят только через MCP, негативные тесты | шаги 2–3 |
| 5 | Цифровой двойник одного процесса | воспроизводимый сценарий, сравнение альтернатив | шаг 2 |
| 6 | Управляемый контур улучшения | ночной анализ, реестр проблем на живых событиях, регрессии | шаг 5 |

Этапы 1–2 можно начинать сейчас. Этап 3 заблокирован отсутствием параметров OPC UA.

## 6. Подтверждение безопасности

- Категория C (исполнение) отключена в `tools.py`, `web_app.py`, `scada_agent.py`.
- Универсальных инструментов записи нет.
- Запись в 1С возможна только через `confirmed_by`, подтверждение проверяется кодом, а не моделью.
- Недоступность ИИ не влияет на оборудование: платформа только читает.
