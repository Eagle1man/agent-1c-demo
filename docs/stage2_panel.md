# Шаг 2: единый интерфейс на живых данных 1С

**Дата:** 01.11.2026
**Файлы:** `agent/panel_server.py`, `tools/check_panel.py`, `tools/run_epf.py`.
**Проверка:** `py tools/check_panel.py` → 13/13 PASS.

## Что это

Один экран: панель предприятия и чат. Данные берутся **только из живой 1С** через
файловый мост; демо-значения не подставляются.

Запуск:

```powershell
py agent\panel_server.py --port 8077
```

Открыть: `http://127.0.0.1:8077`

## Что показывает

| Блок | Источник | Пример (01.11.2026) |
|---|---|---|
| Состояние моста | `проверка_связи` | ok, мост 1.0, время ответа |
| Документов реализации | `КОЛИЧЕСТВО(*)` по `Документ.РеализацияТоваровУслуг` | 385 |
| Контрагентов | `Справочник.Контрагенты` | 12 |
| Позиций номенклатуры | `Справочник.Номенклатура` | 20 |
| Последние 5 документов | номер, дата, контрагент | 000000385 от 26.09.2026, ООО Клевер |

У каждого блока — источник и время получения. Если мост молчит: красная плашка
«1С НЕДОСТУПНА» с текстом ошибки и временем; числа становятся `—`, а не нулями.

## Чат: два маршрута

| Вопрос | Куда идёт | Ответ |
|---|---|---|
| «покажи последние документы» | 1С (детерминированный запрос) | список документов с датами и контрагентами |
| «сколько контрагентов» | 1С | «Контрагентов в базе: 12» |
| «как создать внешнюю печатную форму» | RAG | фрагмент базы знаний 1С с указанием файла |

Маршрут выбирается по ключевым словам, а не моделью: на этом шаге важно, чтобы
данные приходили из 1С предсказуемо. Замена маршрутизации на модель — отдельный
шаг, после того как панель принята.

## API

| Метод | Путь | Что отдаёт |
|---|---|---|
| GET | `/` | страница (чат + панель) |
| GET | `/api/health` | статус моста, версия, время |
| GET | `/api/panel` | счётчики, последние документы, номенклатура, ошибки |
| POST | `/api/ask` | `{phrase}` → `{kind: data|rag, answer, source, ts}` |

## Что проверено

`py tools/check_panel.py` — 13 проверок: мост отвечает, счётчики > 0, у данных
есть источник и время, вопрос про данные уходит в 1С, вопрос по знаниям — в RAG,
и главное: **без 1С панель показывает ошибку, а не выдуманные числа**
(проверяется подменой каталога обмена на несуществующий).

## Ограничения этого шага

- Маршрутизация чата — по ключевым словам, без модели.
- Панель показывает сводку, а не карточку отдельного заказа.
- OPC UA не подключён: производственных данных в панели нет (этап 3).
- Версия платформы в ответе моста — заглушка `8.3` (см. `docs/integration_inventory.md`).
