# Модельная политика: кто на какой модели работает

**Дата:** 31.10.2026
**Основание:** ТЗ §6 (роль ≠ модель), §28 (не менять модель без измеримого основания), §22 (разный контекст разным агентам).
**Проверено:** карточки и размеры файлов взяты из Hugging Face API 31.10.2026, не из пересказа.

## 1. Почему одна модель на всё не подходит

Замер этапа B (`docs/stage_b_rag.md`): поиск перестал быть узким местом, узкое
место — генерация. Доступные локально модели 1.5–7B не держат инструкцию
«отвечай только по контексту»:

| Модель | Время | Результат |
|---|---|---|
| `qwen2.5:1.5b` | 28.6 с | ответ не по делу |
| `vikhr-qd-a:latest` | 57.8 с | реплика форумчанина вместо ответа |

Отсюда разделение: быстрая модель для диалога и оркестрации, крупная
специализированная — для тяжёлых задач, эмбеддинги — отдельно.

## 2. Выбор по ролям

| Роль | Модель | Размер | Где работает | Почему |
|---|---|---|---|---|
| `coordinator`, `agent` (диалог, маршрутизация) | `qwen2.5:7b-instruct` Q4 | ~4.7 ГБ | основная машина | 7B держит инструкцию заметно лучше 1.5B; на CPU 8–12 ток/с |
| `analyst` (ночной разбор, этап C) | `sweetand/qwen3.8-27b-1C` **Q3_K_M** | 13.5 ГБ | ВМ 24 ГБ | крупная модель для анализа без спешки |
| `code_expert` (BSL, запросы, метаданные) | `sweetand/qwen3.8-27b-1C` **Q3_K_M** | 13.5 ГБ | ВМ 24 ГБ | дообучена на 1С: BSL, XML-выгрузки, язык запросов |
| `scada` (сводки по авариям) | `qwen2.5:7b-instruct` | ~4.7 ГБ | основная машина | отдельной надёжной русской SCADA-модели нет |
| RAG форума 1С | `paraphrase-multilingual-MiniLM-L12-v2` | ~470 МБ | везде | измерено: hit@3 100%, MRR 0.85 |
| RAG по коду/BSL | `PruhaNLP/USER2-1C-code` | 149M, 1.2 ГБ | везде | ModernBERT, ru, обучена на 1C-Ebench |

## 3. quantized 27B на ВМ 24 ГБ: что реально влезает

Файлы `sweetand/qwen3.8-27b-1C` (проверено в API HF):

| Квант | Размер | Влезает в 24 ГБ с ОС и KV-кэшем |
|---|---|---|
| Q2_K | 10.9 ГБ | да, качество заметно ниже |
| Q3_K_S | 12.3 ГБ | да, с запасом |
| **Q3_K_M** | **13.5 ГБ** | **да — рекомендуемый** |
| Q3_K_L | 14.6 ГБ | да, впритык |
| Q4_0 | 15.7 ГБ | да, но без запаса (Windows уйдёт в swap) |
| Q8_0 | 29.0 ГБ | нет |

Бюджет для Q3_K_M: модель 13.5 + KV-кэш 8k ≈ 1.5 + Windows 4 + Python 1 ≈ **20 ГБ из 24**.

`mmproj` (0.9 ГБ, зрение) не нужен: проект работает с текстом.

**Скорость — главное ограничение.** На CPU без GPU 27B даёт порядка 1–3 ток/с
(если архитектура плотная). Ответ на 300 токенов — 2–5 минут. Поэтому:

- **не** ставить эту модель на диалог с пользователем;
- использовать для ночного анализа, разбора BSL-кода, подготовки отчётов;
- перед приёмкой измерить фактическую скорость на своей ВМ: `ollama run ... --verbose`.

Если у ВМ есть GPU (даже 12 ГБ), Q4_0 поместится частично на видеоядро и
скорость вырастет в разы — тогда переходить на Q4_0.

## 4. Про модели, которые предлагались для SCADA

Проверены карточки:

| Модель | Что это на самом деле | Решение |
|---|---|---|
| `Similoluwa/IndustrialIntel-1.7B-GGUF` | Qwen3-1.7B + LoRA, **английский**, 30 скачиваний | не основа: только как эксперимент для англоязычных сводок |
| `nepetai/Fern-gear-200M-73M-A-IND` | 200M MoE, en/ar/ja, 10 скачиваний | не берём: размер и языки не подходят |

Вывод: **отдельной надёжной SCADA-модели под русский язык нет.** Сводки по
авариям делает обычная instruct-модель, а решение о том, что считать аварией,
принимает детерминированный код (`agent/scada_bridge.py`, пороги датчиков) —
ТЗ §28 прямо запрещает делать LLM механизмом проверки безопасности.

## 5. Как включить

Имена ролей и моделей вынесены в `agent/config.json` → `model_roles`.
Проверить, что реально будет использоваться:

```powershell
py agent\models.py
```

Если модель роли не установлена, система берёт базовую и **сообщает об этом** —
молчаливого переключения нет.

Установка на ВМ 24 ГБ:

```powershell
# 27B под 1С (Q3_K_M, 13.5 ГБ)
ollama pull hf.co/sweetand/qwen3.8-27b-1C:Q3_K_M
# если тег не распознан — скачать GGUF-файл qwen3.8-27b-1c-Q3_K_M.gguf и собрать через Modelfile

# диалоговая 7B
ollama pull qwen2.5:7b-instruct
```
